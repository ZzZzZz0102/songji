# 云览松溉·数启乡兴：可运行业务版

项目目录：`D:\codex\songgai-business`。原网站目录未覆盖。本版基于本机已有网页源码扩展；本次环境未能读取 `https://songji.pages.dev/` 的在线内容，因此不能保证线上后续改动均已合并。

## 启动与访问

需要 Node.js 24 或更新版本。后端使用 Node 内置 SQLite，无需安装数据库或后端 npm 依赖；查看器依赖已保存在 `public/vendor/`。

双击 `启动网站.cmd`，保持打开的终端运行，然后访问：

<http://127.0.0.1:8787/>

也可以在项目目录执行：

```powershell
node tools/bootstrap-local.mjs
node server/main.mjs
```

首次启动只创建随机密码的管理员。账号在 `data/initial-admin.txt`，该文件不会通过网站提供。登录后到“我的账号”修改密码；改密会注销所有设备。不要把初始密码、`.env`、`data/` 或数据库发到公开网站。原有本机意向与正式预约分别显示，旧浏览器草稿不会自动迁移到新的网址。

## 试用流程

1. 管理员登录，进入“业务工作台 → 商户管理”，为已核对经营主体的商户开账号，填写接待地点、公开联系信息和核验依据。没有实际商户时请只在隔离测试环境试用，不要将虚拟主体核验为合作商户。
2. 商户独立登录，在“预约工作台 → 添加体验课程”填写点位、价格、时段、人数和取消说明，保存后发布。
3. 游客注册账号，在“体验预约”选择日期、时段、人数并提交。预约进入相应商户收件箱；商户确认或拒绝，双方可以回复。商户工作台每 20 秒读取新记录。
4. 同一游客账号换浏览器登录，可读取服务器上的预约及回复。此能力要求两台设备访问同一个运行中的后端。
5. 实际业务发生后，商户在“业务凭证”上传收款、退款、到户款、劳务费、成本凭证，管理员人工复核；“运营记录”仅汇总通过复核的记录。

本地测试不会发短信或收钱。工作台是当前实际接收渠道；可选通知中继由环境变量配置。通知中继失败不影响商户收件箱。游客付款与银行到账核验尚未接入。

## 真实三维成果的制作与登记

查看器并不是建模成果。本项目没有通过照片或视频虚构古镇 3DGS，也没有把合成测试球体当作古建筑。

- 3DGS：取得采集与展示授权，采集有重叠视角的原始影像，完成相机标定和 SfM，再训练高斯模型，检查漂浮物、遮挡、尺度和效果；导出带高斯属性的 PLY、SPLAT 或 KSPLAT。本站接收并显示成果，不包含 SfM 或训练流水线。普通 PLY 点云会被拒绝登记为 3DGS。
- HBIM：实测坐标基准、建筑编号、构件编号、材料、尺寸、病害、检查日期、修缮记录及证据。管理员登记结构化档案，可关联实际 IFC。当前实现档案浏览与源文件下载，未实现 IFC 构件三维选择或自动病害诊断。
- AR：上传纹理和缓冲内嵌的 GLB，并登记模型实际宽度（米）。查看器按此缩放，通过 WebXR、Android Scene Viewer 或 iOS Quick Look 尝试启动。它是空间放置体验，未实现古建筑实景配准或图像识别叠加。

管理员在“资产管理”上传文件、登记来源和核对依据后公开。GLB 不是保护用 HBIM，浏览器画面不代表满足测绘精度。资产公开后可供访问者下载，请先核对授权。AR 的设备支持、系统权限和实际比例必须在支持的实体手机上检查；桌面和模拟手机测试不能替代此步骤。

## 知识库与模型配置

共享资料在 `server/catalog.json`，沿用原网站点位和二维码路线顺序。`node tools/build-catalog.mjs` 可从原站数据重新导出。引用来源不代表其现场开放信息已核实。本机补录草稿不会自动作为服务器知识库事实。

复制 `.env.example` 为 `.env`，在本机编辑：

```dotenv
LLM_BASE_URL=https://你的服务域名/v1
LLM_API_KEY=在本机填写
LLM_MODEL=服务支持的模型名称
```

接口需兼容 `POST /chat/completions`，返回文本中的 JSON 答案与来源编号。模型供应商会收到问题和检索片段，切勿在问题中填写敏感资料。密钥只由后端读取。未配置时页面显示“知识检索”，不会假称已接入大模型；配置后供应商失败、JSON 错误或引用编号不合法均回退到原文。引用编号校验不能自动保证每个陈述事实正确，仍需人工抽查。

当前本机使用火山方舟 `https://ark.cn-beijing.volces.com/api/v3` 和模型 `doubao-seed-2-1-pro-260915`。API Key 只存放在项目根目录 `.env`；控制台的密钥名称是管理标签，不是请求中的模型名称或鉴权值。方舟请求使用 JSON 输出并关闭深度思考，以适配导览短问答的响应时间；答案仍按网站知识库检索结果生成和校验引用。更换密钥后重新启动服务即可生效，不要把 `.env` 上传到静态网站。

## 财务口径

金额按人民币分存储，预约参考总额不算成交。凭证保留 SHA-256，平台人工复核后计入汇总；这不等于银行或支付接口验证。商户只能查看自己的预约和凭证。收款上限为预约报价，退款不能超过收款，到户款、劳务和成本合计不能超过净收入。预约履约后才可登记到户分配与成本。已复核记录不可直接改写，错误待审记录由平台拒绝后重新登记。

这是预约及人工凭证流程，尚未包含支付、转账、电子发票、复杂对账或已分账后资金追缴。涉及这些实际业务时需接入支付及财务系统。

## 跨设备、部署与备份

### 当前临时公网 HTTPS 演示

本机已使用 Cloudflare Quick Tunnel 提供临时公网访问。双击 `开启公网演示.cmd` 可启动并显示网址；双击 `停止公网演示.cmd` 可关闭。也可执行 `node tools/public-demo.mjs start`、`status`、`stop`。当前网址写在私有的 `data/public-demo.json` 中，该文件还包含本机控制凭据，不要发送整个文件，只分享其中的网址。

这是运行在本机的临时演示入口，不是全天候云托管。电脑关机、睡眠、断网或关闭隧道都会中断访问，重新启动可能获得不同网址。临时隧道不承诺可用性或固定域名，不能保证所有地区和网络都可访问。

公网实例使用独立的本机监听端口，和原 `http://127.0.0.1:8787` 共用数据库；不会将整个磁盘或项目根目录公开。公网 Cookie 带 Secure，写操作校验公网 Origin，二维码指向公网地址，豆包密钥仍仅在后端。公开页面可被任何获得链接的人浏览，账号及凭证仍受后台权限控制。

公网演示默认每轮24小时最多尝试100次全站大模型调用，达到上限后继续提供原文知识检索；原有每账号每分钟限流仍有效。可在本机环境变量设置 `PUBLIC_DEMO_LLM_MAX_CALLS` 后重启演示实例调整。该限制只限制本应用请求次数，不代替供应商账单额度。

Cloudflared 官方二进制位于 `tools/bin/`，由 `tools/fetch-cloudflared.py` 下载，并对照官方发布的 SHA-256 校验。它不属于网站静态资源，也不会复制进容器镜像。公网运行日志位于 `data/cloudflared.log`、`data/public-server.log`；运行 `node tools/check-public-demo.mjs` 可验证公网 HTTPS、登录、豆包问答、二维码和手机布局，并在 `test-results/` 生成不含密钥的报告。该检查需要初始管理员密码尚未更改及本机浏览器测试依赖。

### 长期托管

Cloudflare Pages 静态托管不能直接运行本 Node + SQLite 服务。上线需 Node 24 服务器或带持久化磁盘的容器，并通过 HTTPS 提供网站和 API。也可保留 Pages 前端，但必须将 `/api/`、`/media/`、`/private-files/` 反向代理到同一业务服务，保持同源 Cookie 和请求来源配置。不要只上传 `public/` 后宣称后台可用。

局域网试用时在 `.env` 设置 `HOST=0.0.0.0`，将 `APP_ORIGIN` 设为电脑实际局域网 IP 和端口，例如 `http://192.168.1.20:8787`，所有设备用这个地址访问，按需配置 Windows 防火墙。局域网 HTTP 不满足手机 AR 安全连接要求。公网部署使用真实 HTTPS 地址作为 `APP_ORIGIN`，后端 Cookie 自动采用 Secure。二维码按该地址生成；127.0.0.1 二维码只能指向扫码设备自身。

Dockerfile 已提供。容器的 `/data` 必须绑定持久化目录；用环境变量配置管理员，执行 `node tools/create-admin.mjs` 建立账号。不要将数据写进临时容器层。

备份前先正常停止服务，然后整体复制 `data/`（数据库、WAL 及资产文件）；只复制 SQLite 主文件可能遗漏 WAL 中的新记录。恢复时设置正确 `DATA_DIR`。数据包含用户和业务凭证，应限制磁盘访问并建立实际备份与保留制度。

## 验证

```powershell
node --test tests/business.test.mjs tests/rag.test.mjs tests/proxy.test.mjs
node tests/browser-qa.mjs
```

后者需要 Playwright、Chrome 和 sharp；默认使用本机 Codex 自带依赖，也可通过 `PLAYWRIGHT_MODULE`、`SHARP_MODULE`、`CHROME_PATH` 指向已安装的位置。测试在 `data/` 内创建独立数据库，结束后删除，不写入正式数据库。截图和验证报告在 `test-results/`，其中三维几何为明确标注的合成测试素材。

`tools/fetch-vendor.py` 可重新获取固定版本的依赖，传入文件名强制重新下载。来源、版本和 SHA-256 在 `public/vendor/manifest.json`，同目录保留许可证。首次本地试用无需再次下载。
